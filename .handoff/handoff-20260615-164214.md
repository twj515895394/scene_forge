## 最新发现

用户反馈 Web Console 中 Claude 聊天 token 消耗过大。经诊断，根因不在前端泡泡渲染，也不是 Web Console 手动把 history / toolcall / thought 拼回 prompt。

当前后端行为是：

- 首轮：`claude --print ... <project context + 用户输入> --session-id <sessionId>`
- 后续：`claude --print ... <用户输入> --resume <sessionId>`

长期 `--resume` 会让 Claude CLI 自己恢复本机 session JSONL。SceneForge 阶段执行中产生的 `thinking`、`tool_use`、`tool_result`、file snapshots、assistant 输出会不断进入 session 历史，导致 token 滚雪球。

已做过的本机统计示例：

```text
projects/worldcup003:
  jsonl size: ~3465KB
  lines: 1169
  assistant: 608
  user: 296
  thinking: 263
  tool_use: 278
  tool_result: 278
  file-history-snapshot: 85
```

结论：这是 P0 级架构问题。

## 重要设计边界

- 不管理任何 secret。
- 不读取、不保存、不展示 `baseUrl`、`apiKey` 或供应商配置。
- 不裁剪 Claude CLI JSONL 再强行 resume。
- 不删除真实项目产物。
- 不提交 `projects/*`、`PROJECT_STATE.json`、`artifacts.manifest.yaml`、`runtime/` 等运行产物，除非用户明确要求。
