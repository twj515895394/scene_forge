## 聊天界面未解决问题

这是给下一个代理最重要的参考区，避免继续重复走弯路。

### 问题 1: 聊天区仍出现大量横线 / 大空白块

现象:

- 历史会话和实时输出之间，常出现多段横线样式的大空白区
- 用户多次截图确认:
  - 并不是单纯“段落间距稍大”
  - 而是像大量 `<hr>` 或空白 markdown block 被渲染出来

当前判断:

- 这个问题大概率不是单一 CSS 问题
- 更像是“消息内容进入前端前就带有 markdown 分隔线 / 空块”，再叠加前端渲染后被放大
- 也可能是“历史重建链路”和“实时 websocket 输出链路”对同一类内容的归一化逻辑不一致

### 问题 2: 历史消息存在重复内容

现象:

- 同一条 AI 回复有时出现两次
- 用户多次截图展示过重复段落 / 重复卡片

当前判断:

- 大概率出在 websocket merge / history replay / normalized dedupe 三段链路之一
- 不是单纯 React key 或 CSS 问题

### 问题 3: prompt card / 审批卡片稳定性不足

现象:

- 之前用户要求审批卡片、确认卡片、交互卡片能正常出现
- 目前相关链路虽然做过多轮修改，但整体稳定性仍不能算真正闭环

### 已尝试过的修复方向

以下方向都已经做过，不建议下个代理再从最浅层重复试:

1. 前端样式层压缩间距 / 隐藏横线
   - 调过聊天正文、预览区、列表、标题、段落、表格等样式
   - 结果: 只能改善视觉密度，不能根治横线来源

2. 前端消息去重 / renderable 过滤
   - 做过 bubbles / history / ws output 的诊断日志
   - 结果: 仍有重复与异常渲染残留

3. 针对思考流 / 空 thinking block 的过滤
   - 之前已定位过一部分历史 thinking 空块问题
   - 结果: 能减少一部分空白，但不是横线问题的最终根因

4. 尝试直接隐藏 `<hr>`
   - 用户后续已明确表示: 如果定位太难，可以先把这类横线彻底不显示
   - 但最近一轮仍未达到“横线数量明显下降”的效果

### 建议后续处理方式

不要再把这个问题当作“纯 CSS 微调”。

下个代理应该按专项疑难问题来查，重点拆成两条链路:

1. 实时输出展示链路
   - websocket 事件原始 payload
   - transform / merge / normalize
   - Variant B feed render

2. 历史回放展示链路
   - session / persisted message source
   - history rebuild
   - markdown 渲染输入

关键要回答的问题:

- 横线到底来自:
  - 原始 markdown 里的 `---`
  - 空 block 被转成 `<hr>`
  - 多段 separator 被保留下来
  - 历史 replay 拼接逻辑
  - 还是 render 阶段误判

如果继续排查，建议直接开新 issue 做专项，不要夹在视觉微调里继续修。

  - `pack_mode: multi_pack`
  - `total_packs: 8`
  - `total_shots: 88`

- storyboard 阶段的“质量检查通过”并不可信
- 当前 validator / check 只能证明最低限度通过，不能证明真实符合交付规范

### 4. 更深层问题: 当前 validator 过浅

从 `PROJECT_STATE.json` 的历史记录看，多个阶段都经历过:

- 先校验失败
- 再补一个关键 section
- 然后通过

这说明现在的校验更像:

- “最低限度结构存在即可通过”

而不是:

- “真正符合该阶段完整输出契约”

所以后续真正要补的是:

1. 阶段顺序约束
2. 阶段执行过程约束
3. 阶段产物结构和内容的完整契约校验

而不是只改 UI 或只改 `state_machine.ts`
