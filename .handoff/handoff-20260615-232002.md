### 2.2 阶段 session 模型

主要文件：

- `apps/web-console/server/server.ts`
- `projects/test061501/.scene_forge_session_meta.json`

当前设计：

- 一个 SOP 阶段对应一个 Claude session。
- 当前阶段 session 从项目 metadata 读取：

```json
{
  "sessions": {
    "topic_gate": {
      "sessionId": "43676f56-ebb3-4362-bc32-a3ccb3c66a3f"
    }
  }
}
```

- 普通对话不会新建 session，只会复用当前阶段 session。
- 只有执行阶段 `complete`，并且 Claude 结束后服务端读取 `PROJECT_STATE.json` 确认该阶段已经 `completed`，才切到下一个阶段并 `getStageSession(nextStage)`。
- 触发链路不是定时任务：
  1. 前端发送阶段动作 `complete`。
  2. 服务端记录 `pendingCompleteStage`。
  3. 服务端让 Claude 执行 `node ../../packages/engine/dist/cli.js complete --stage <stage>`。
  4. CLI 推进 `PROJECT_STATE.json`。
  5. Claude 进程 close 后，服务端确认 stage completed。
  6. 服务端切到下阶段 session，并通过 WebSocket 发 `session_init` / `stage_session`。

  - 根据当前 `PROJECT_STATE.current_stage` 获取 stage session。
  - 通过 `getSessionJsonlPath(sessionId, targetPath)` 同时查项目 session dir 和 workspaceRoot session dir。
  - 找到历史后发送 `history` bubbles，聊天框中间可以恢复显示。

