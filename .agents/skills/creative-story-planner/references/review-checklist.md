# Creative Story Planner Review Checklist

在输出 `01_CREATIVE_STORY.md` 前逐项检查。

## 创作方向

- [ ] `original / rewrite_adaptation / preserve_original` 已明确。
- [ ] 用户已明确选择的创作模式没有被擅自改变。
- [ ] 如存在 adaptation idea，已继承用户真正选择的方向。
- [ ] 如选择 preserve original，没有偷偷改成新题材。

## 参考边界

- [ ] 有参考源时已经写明 `must_keep / should_keep / allowed_to_rewrite / must_avoid`。
- [ ] `must_avoid` 没有在后续故事中重新出现。
- [ ] 没有为了规避参考而破坏用户真正想保留的核心桥段。

## 故事结构

- [ ] Logline 可以一句话说明故事。
- [ ] 主角目标、阻力、冲突清楚。
- [ ] 起点、升级、高潮、结局完整。
- [ ] 结局与前面的铺垫一致。
- [ ] Story Beats 没有两个连续 Beat 承担完全相同功能。
- [ ] 每个 Beat 都有明确的状态变化。
- [ ] Beat 数量与目标时长匹配。

## 角色

- [ ] 所有重要角色都有稳定 `CHAR_###` ID。
- [ ] 角色功能和关系清楚。
- [ ] 没有提前写成完整视觉设定。
- [ ] 角色弧光与 Story Beats 一致。

## 时长与节奏

- [ ] Beat 估时总和与目标总时长基本一致。
- [ ] 高潮没有被压缩到无法成立。
- [ ] 开场没有占用过多时长。
- [ ] 若存在 segment strategy，已作为建议或确认值准确标记。

## 风格

- [ ] 风格方向足够让下游理解，但还没有变成图片 Prompt。
- [ ] 未确认的风格没有伪造成 confirmed。
- [ ] 叙事风格与题材、受众和时长匹配。

## 连续性

- [ ] 首批稳定实体 ID 已建立。
- [ ] 关键 story facts 已记录。
- [ ] 下游不会因为缺少故事事实而重新猜测人物关系或剧情方向。

## 输出纪律

- [ ] 唯一正式输出是 `01_CREATIVE_STORY.md`。
- [ ] review 没有单独落成第二份正式文档。
- [ ] 没有声称已经生成图片、音频或视频。
- [ ] `Downstream Handoff` 完整。
