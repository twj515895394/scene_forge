# Web Console Artifact Consistency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use planning-with-files to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复 SceneForge Web Console 与 Engine 在阶段完成、产物索引、manifest 注册和聊天实时回复去重上的一致性缺口。

**Architecture:** 先在 Web Console 抽出纯产物发现模块，为 UI 提供 manifest、PROJECT_BOARD 和磁盘文件的合并视图；再在 Engine complete/validate 链路补自动同步与一致性检查，避免新项目再次出现 state completed 但 board/manifest 脱节。聊天重复问题作为独立薄切片处理，只收口 assistant text 跨 bubble 重复，不触碰 thought/tool/prompt 生命周期。

**Tech Stack:** TypeScript, Node.js, Express, js-yaml, node:test, SceneForge Engine CLI.

---

## 已核实问题

- `projects/worldcup/PROJECT_STATE.json` 中 `storyboard`、`audio`、`video_prompts` 已是 `completed`。
- `projects/worldcup/PROJECT_BOARD.md` 中 `storyboard`、`audio`、`video_prompts`、`publish` 的 `stage_index` 仍为 `pending` 且 `files` 为空。
- `projects/worldcup/artifacts.manifest.yaml` 只注册主交付，未完整覆盖 `details/` 与子 `outputs/`。
- `apps/web-console/server/server.ts` 的 `/api/artifacts` 只合并 manifest 与 board，没有磁盘扫描兜底。
- `node ../../packages/engine/dist/cli.js validate --stage storyboard --json` 与 `validate --stage video_prompts --json` 当前均可通过，说明 validator 尚未覆盖 board/manifest 一致性。
- 实时聊天链路已有前端连续 text 去重，但 server/merge 层仍可能产生不同 id 的同语义 assistant text。

## 风险与回滚

- 自动同步必须只注册真实存在的文件，不能生成虚假产物。
- 阶段命名映射必须集中处理，避免 `publish` 与 `publish_review` 在 UI/CLI 之间继续漂移。
- Web Console 磁盘兜底只负责展示防线，不能替代 CLI/validator 的质量判断。
- 若 validator 新规则误伤旧测试项目，应降级为 warning 或要求测试项目补最小 board，而不是放宽生产项目一致性。
