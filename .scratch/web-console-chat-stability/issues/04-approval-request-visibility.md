# Issue 04: 审批请求可见性修复

## 父问题

[PRD.md](file:///Users/tangwujun/Documents/trae_projects/scene_forge/.scratch/web-console-chat-stability/PRD.md)

## 要构建什么

当前用户在 `test-project-001` 中触发需要审批的操作时，审批卡片经常根本不显示，说明从后端检测审批请求到前端展示的链路并不稳定。需要先修复“审批请求必须能被看到”这条路径，确保后端能稳定产出审批请求事件，前端能在聊天流中正确渲染出审批卡片。

此切片完成后，用户触发写盘、执行命令或权限确认时，界面中一定能出现对应审批卡片，而不是静默卡住或直接没有 UI。

## 验收标准

- [ ] 在 `test-project-001` 中触发至少一种需要审批的操作时，聊天区能稳定出现审批卡片。
- [ ] 审批卡片必须携带足够的上下文信息，例如标题、动作说明或选项，而不是只有空白占位。
- [ ] 当没有审批请求时，不会错误渲染幽灵卡片或残留卡片。

## Code Review 严格验收标准

- [ ] 审查必须确认审批请求不是靠脆弱的字符串偶然命中才显示，而是有清晰的检测与投递路径。
- [ ] 必须有测试覆盖“请求存在时显示卡片”和“请求不存在时不显示卡片”两种场景。
- [ ] 若本票仍需沿用 CLI 文本拦截，也必须在票内明确局限性并为下一票的结构化交互预留稳定字段，不允许继续扩大技术债。
