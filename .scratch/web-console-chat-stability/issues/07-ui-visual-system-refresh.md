# Issue 07: Web Console UI 视觉系统与侧栏产物布局重构

## 父问题

[PRD.md](file:///Users/tangwujun/Documents/trae_projects/scene_forge/.scratch/web-console-chat-stability/PRD.md)

## 要构建什么

当前 `apps/web-console` 的 Variant B 界面已经能承载聊天、阶段流和产物预览，但视觉质量与信息组织仍明显落后于使用体验目标，主要问题集中在两层：

1. **局部布局失衡**：左侧 `Pipeline Flow` 中“各阶段产物列表”在展开后横向过窄、内容整体偏右、层级线弱、文件名截断生硬，导致产物列表更像悬浮补丁，而不是阶段卡片的自然延展。
2. **整体视觉系统粗糙**：字体、字号、字重、色彩、面板层级、间距节奏、背景氛围都还停留在“功能拼装态”，没有形成统一的产品级控制台体验。当前界面过度依赖单一霓虹色和等宽字，导致阅读压力大、密度失衡、重点不清。

这张票不直接要求一次性实现全部 UI 改造，而是要求先形成一份**可执行的视觉系统重构方案**，并把最关键的布局与样式重构边界定义清楚，供后续实现票落地。

## 现状诊断

### 1. 左侧阶段栏问题

- 阶段主卡的标题、状态 badge、chevron 已占据主要横向空间，导致展开区被迫挤到右侧。
- 产物列表使用了“缩进 + 竖线 + 小卡片”的组合，但缩进过深，文件行本身又没有足够宽度，所以文件名很快被截断。
- `FINAL / DRAFT` 标签与文件名争抢横向空间，视觉上把可点击区域压缩得更明显。
- “暂无交付产物”的空态样式太弱，像占位文本，不像结构化空态。

### 2. 聊天区问题

- 用户气泡、AI 气泡、思考区、工具卡片分别在说不同视觉语言，缺少统一的 typography scale 和 spacing rhythm。
- `AI DIRECTOR` 标题、正文、代码、高亮词都在抢视觉注意力，层级噪声偏大。
- 等宽字体使用范围过宽，正文也带有明显“终端感”，不适合长文本阅读。

### 3. 全局视觉系统问题

- 当前色彩是“黑底 + 青色 + 品红”的旧式赛博风拼接，品牌感不稳定，也不够耐看。
- 背景层次偏平，面板边界主要靠细线和高对比硬切，缺少柔和但清晰的景深层级。
- 字号和字重跨度不成体系：小字太小，标题太硬，中间层过少，导致信息阅读时不是“浏览”，而是“逐块辨认”。

## 设计参考提炼

参考你给的 Codex 界面截图，可以提炼出几条值得借鉴的原则，不是机械照搬，而是迁移其体验逻辑：

1. **弱装饰、强层级**：Codex 界面并不依赖大量亮色，而是靠背景层、面板边框、留白和字重来建立结构。
2. **正文优先**：正文使用更适合长阅读的无衬线字体，等宽字体只用于路径、标签、代码、元信息。
3. **高密但不拥挤**：信息密度高，但通过一致的间距节奏和卡片圆角控制，让界面看起来稳而不乱。
4. **边栏像导航，不像仪表盘**：左栏项目/线程列表更强调“列表可扫读性”，不是到处强调状态灯和发光边框。
5. **低饱和暗色基底**：整体是温和深色，不是纯黑；强调内容，而不是强调霓虹效果本身。

## 建议的视觉方向

### 方向名

**Quiet Command Center**

### 核心特征

- 基底改为“暖灰黑 / 石墨黑”，弱化纯黑背景。
- 主强调色从高饱和青色收窄为“冷蓝青”单主轴，品红只保留为极少数状态点缀，不再大面积出现。
- 正文字体切换为更现代、更耐读的 sans-serif；等宽字体只保留在 stage 编号、状态 badge、文件标签、代码片段中。
- 圆角、阴影、描边全部收敛，减少“赛博组件库拼装感”。

## 设计优化方案

### A. 侧栏与阶段产物列表

#### 目标

让 `Pipeline Flow` 既像阶段导航，也像可展开的交付索引树；展开后内容应自然靠左对齐，并与阶段卡片保持一个连续结构。

#### 方案

- 降低产物列表的左缩进深度，把“阶段卡片”和“产物列表”做成更明确的父子结构。
- 展开区域改成整块浅层背景容器，而不是当前“竖线 + 浮动文本行”的弱容器。
- 文件行拆成三列：
  - 文件图标
  - 可伸缩文件名
  - 固定宽度 kind badge
- kind badge 使用更轻、更短的标签样式，例如 `Final / Draft / Review`，避免压迫文件名空间。
- 文件名 hover 时显示完整路径 tooltip，但默认只显示文件名，不在行内塞路径。
- “暂无交付产物”使用标准空态容器，和有产物时的区域保持同样的结构边界。

#### 成功标准

- 文件列表视觉重心回到左侧，而不是被 badge 和右侧空白挤压。
- 单条产物在 320px 左右侧栏宽度下仍可稳定识别文件名。
- 展开/收起后的父子关系一眼可理解。

### B. 全局排版系统

#### 目标

建立统一的字体、字号、字重、行高体系，减少“全界面都像终端”的噪音。

#### 方案

- 正文层：使用现代 sans-serif 作为主要阅读字体。
- 元信息层：保留 JetBrains Mono 或同类等宽字体，仅用于 stage index、badge、时间、路径、代码。
- 建立明确字号刻度：
  - 页面标题 / 区块标题
  - 列表标题 / 卡片标题
  - 正文
  - 辅助说明
  - 元数据
- 减少超小字号；当前很多 8px/9px 的字已经逼近“可见但不可读”。

#### 成功标准

- 长文本聊天消息可连续阅读，不再有强烈的“密集终端输出”感。
- 侧栏列表扫读效率明显提升。
- 代码、标签、元信息仍保留控制台工具感，但正文不再被等宽字体污染。

### C. 色彩与层级系统

#### 目标

让界面从“高饱和赛博风”转向“安静的专业控制台”。

#### 方案

- 定义全局 token：
  - 背景基底
  - 一级面板背景
  - 二级面板背景
  - 边框
  - 主文本
  - 次文本
  - 主强调色
  - 成功 / 风险 / 警告状态色
- 状态色只服务状态，不再承担品牌表达。
- 大面积面板避免纯黑，改为不同层次的深灰黑。
- 通过轻阴影和低对比描边建立层级，不靠发光边。

#### 成功标准

- 页面层级主要靠深浅和字体层次被识别，而不是靠高亮色块。
- 颜色数量减少，但状态可读性提高。

### D. 聊天气泡与信息密度

#### 目标

统一聊天区各类气泡语言，让用户消息、AI 回复、思考区、工具卡片成为同一系统中的不同变体。

#### 方案

- 用户气泡保留右对齐，但减少高亮渐变强度，避免喧宾夺主。
- AI 回复卡片降低装饰感，强调正文、弱化标题。
- 工具卡片压缩视觉噪声，默认呈现“工具名 + 结果状态 + 摘要”，展开后再看细节。
- 思考区采用更轻的可折叠信息块，不再与正文气泡争夺主舞台。

#### 成功标准

- 聊天区从上到下呈现稳定节奏，不再像多个不同设计稿拼起来。
- 用户能快速区分“结果、过程、工具、审批、元信息”。

## 推荐落地顺序

1. 先做全局 token 与 typography scale。
2. 再重做左侧 stage card 与 artifact list 布局。
3. 然后统一聊天区 4 类气泡的视觉语言。
4. 最后补 hover、空态、选中态、滚动条、微动效等收尾细节。
